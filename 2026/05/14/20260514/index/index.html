三、从 Agent Demo 到赛博聊天室 — 演进路线
阶段一：微服务地基



    

  • 用 Maven 多模块 POM 统一管理版本（Spring Boot 3.3.6 + Cloud 2023.0.3 + Java 17）
    • 

  • user-service / order-service 两个微服务跑通 Nacos 注册发现
    • 

  • order-service 用 OpenFeign 远程调用 user-service，验证跨服务通信
    • 

  • order-service 接入 Kafka，生产者/消费者双向打通
    • 

  • common 抽取共享 DTO，避免重复代码
    • 

  • api-gateway 搭好网关骨架
    • 



这一阶段的关键决策：Nacos 3.x 需要排除旧版 Ribbon 依赖，改用 Spring Cloud LoadBalancer。




阶段二：AI Agent 从零到一



    

  • agent-service 引入 langchain4j-spring-boot-starter + langchain4j-open-ai-spring-boot-starter
    • 

  • 写 DeepSeekConfig：通过 @ConfigurationProperties 把 API Key / Base URL / Model Name 抽到 application.yml
    • 

  • 写 LangChain4jConfig：创建 OpenAiChatModel Bean（改用 DeepSeek 的 baseUrl），配置 ChatMemoryProvider（MessageWindowChatMemory，保留最近 20 条消息）
    • 

  • 写第一个 MyAiService_fenni 接口：@AiService 注解 + @SystemMessage 从文件加载人设 + @MemoryId 支持多会话
    • 

  • AgentController 暴露 POST /ai-agent/fenni，接收 {sessionId, message} 返回 AI 回复
    •

关键技术点：


    

  • LangChain4j 的 @Tool 注解会自动把方法签名 + 描述注入提示词，DeepSeek 自主决定何时调哪个工具
    • 

  • CalculatorTool 因 Java 17 移除了 Nashorn，手写了表达式解析器
    • 

  • FileTool 用 Paths.get(user.dir, "files") 作为沙箱根目录，防止路径穿越
    • 





阶段四：前端聊天室上线



前端选型：Vue 2.7 + Element UI + Vite 4（项目最初用 Vue 2，延续生态）


核心功能实现：


    

  1. Agent 选择器：el-select 下拉切换 6 个角色，每个角色独立 sid
    2. 

  2. 对话管理：左侧对话列表，支持新建/切换/删除，数据存在 localStorage
    3. 

  3. 消息区：用户消息靠右（蓝色），Assistant 靠左（白色），思考中显示加载动画
    4. 

  4. Agent 管理弹窗（AgentDialog.vue）：支持自定义名称/邮箱/授权码/系统设定/本地上传头像
    5. 

  5. 前后端通信：Vite proxy 将 /ai-agent 转发到 localhost:8084，POST 请求带 {sessionId, message}
    6. 



CSS 迭代细节（踩坑记录）：


    

  • Agent Grid 从 grid 4列 → flex 均分一行 适应 6 个角色的宽度
    • 

  • 所有圆形头像统加 object-position: top，解决竖版图裁切到底部的问题
    • 

  • 移除了 endpoint 路径显示（/fenni），界面更干净
    •

四、架构亮点与设计思路
1. LangChain4j 的声明式 Agent 编程



LangChain4j 自动处理：


    

  • SystemMessage 注入人设
    • 

  • MemoryId 实现会话隔离
    • 

  • @Tool 方法自动注册，DeepSeek 自主决策调用
    • 

  • 消息历史 → ChatMemory → 上下文窗口管理
    •

3. 前后端分离但统一代理



开发阶段零跨域问题，生产环境改 Nginx 配置即可。


4. 微服务体系完整但 agent-service 独立可跑
agent-service 依赖 Nacos 注册发现，但核心功能（AI 对话+工具调用）不依赖其他微服务即可运行。这种设计让 Agent 模块可以独立调试，同时保留了接入微服务生态的扩展性（未来可通过 Feign 调用 user-service 查用户信息，或通过 Kafka 推送消息）。
